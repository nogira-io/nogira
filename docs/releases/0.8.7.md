# NoGira 0.8.7

**Release date:** 2026-11-06

**Board card fields + Priority sort** — Board admins can pick up to three scheme fields (searchable picker) shown on Kanban/Scrum cards between summary and assignee. Empty values show muted **None**. Parent resolves from the activity parent. Priority sort on boards is **high → low**; `/home/search` Priority column is sortable with the same weight semantics.

**Tracking:** **NG-743** / **NGF-088**, **NG-744** / **NGB-094**, **NGF-007**, **NGF-016**, **NGF-008**. Public installer sample compose stays on **`latest`**. Candidate tag promoted: **`dev-8a89ef3`**.

## Assets

- No GIF or screenshot required for this patch.

## Added

- Board `configuration.cardExtraFields` (`version: 1`, ≤3 field ids) on create/settings; activity lists enrich `cardFields` for display (**NG-743** / **NGF-088**).
- Search sort key **`priority`** (`sort=priority:desc|asc`) by `priorityOption.weight` (**NG-744**).

## Changed

- Card fields picker: searchable multi-select (Search More-fields chrome); catalog = all scheme fields except Summary, Description, Activity Type, Priority, Assignee, Status.
- Empty configured card fields render **None** (same muted style as Unassigned).
- Parent card field shows parent activity key (or **None**).

## Fixed

- Kanban (and Scrum) Sort → Priority ordered low→high; now high→low by weight; missing priority last (**NGB-094** / **NG-744**).
- Scrum sort menu now applies shared `sortActivities` to the active-sprint card list.
- Search Priority column had no sort control; first click is high→low (**NG-744**).

## Verified

- Local + QA e2e `board-data-source` (Labels + Parent).
- Hosted **dev** and **UAT** on image tag **`dev-8a89ef3`**.

## Upgrade notes

- Pin `nogira-core`, `nogira-ui`, `nogira-worker`, and `nogira-mcp` to **0.8.7** together when the Hub tags exist, then `docker compose pull && docker compose up -d` (or keep sample `:latest` if that is your eval setup).
- Public installer `docker-compose.yml` is **not** version-pinned in this release (sample stays on **`latest`**).
- No manual SQL for NoGira schema migrations (applied on core startup).
- PostgreSQL remains pinned at `postgres:14` — do not change major version without a PostgreSQL migration procedure ([deployment.md](../deployment.md)).
