# NoGira 0.8.9

**Release date:** 2026-11-07

**Unified search + prefix matching** — Activity text search uses one FTS engine on every surface (Home, global, boards, MCP activity-search, parent-candidates). Prefix queries such as `Tan` match `Tanya` (**NGB-096**). QA stacks can opt into a shared 2 vCPU / 1 GiB cgroup budget for fair perf evidence (**NG-747**).

**Tracking:** **NG-746** / **NG-747** / **NGB-096** / **NGF-041** / **NGF-008** / **NGF-046**. Public installer sample compose stays on **`latest`**. Candidate tag: **`dev-8a89ef3-dirty`**.

## Assets

- No GIF or screenshot required for this patch.

## Added

- Shared `build-prefix-tsquery` helper: last token gets `:*` prefix lexeme matching on Activity and Wiki FTS fields (**NG-746** PR2).
- QA Compose opt-in shared stack cgroup (`NOGIRA_STACK_CGROUP_*`) via `cgroup_parent` + `stack-cgroup-setup.sh` / `stack-cgroup-validate.sh` (**NG-747**; local handbook stacks unchanged).

## Changed

- Activity text `q` (≥2) always uses the Activity FTS engine; sort (`lastActivity`, `updatedAt`, relevance) no longer selects Prisma `contains` (**NG-746** PR1).
- MCP activity-search, parent-candidates, and legacy Activity text routes route through the same FTS engine.
- Wiki search ORs the same prefix tsquery branch as Activity.

## Fixed

- Home / search required a full word token (`Tan` missed `Tanya`) — prefix FTS (**NGB-096**).

## Verified

- Local + QA API: `q=Tan` → Tanya; EXPLAIN Bitmap Index Scan on `Activity_fts_gin`.
- QA e2e under cgroup: 29 passed / 2 failed (form-submit + saved-filter labels; not search).
- `perf:smoke` under `nogira-qa` 2 vCPU / 1G: 100% checks; p95 ≈ 688.5 ms (~1.46× vs unconstrained; Gate 3A pass).
- Destin: **`dev-8a89ef3-dirty`**.

## Upgrade notes

- Pin `nogira-core`, `nogira-ui`, `nogira-worker`, and `nogira-mcp` to **0.8.9** together when the Hub tags exist, then `docker compose pull && docker compose up -d` (or keep sample `:latest` if that is your eval setup).
- Public installer `docker-compose.yml` is **not** version-pinned in this release (sample stays on **`latest`**).
- No manual SQL for NoGira schema migrations (applied on core startup). Prefix matching uses existing NG-605-P1 GIN indexes.
- PostgreSQL remains pinned at `postgres:14` — do not change major version without a PostgreSQL migration procedure ([deployment.md](../deployment.md)).
