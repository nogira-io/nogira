# NoGira 0.1.8

**Release date:** 2026-05-29

## Added

- **Create workspace on Home** — `/home/workspaces` now has the same **Create Workspace** action as admin **Manage workspaces**, gated by a server-side creation policy.
- **Workspace creation policy API** — `GET /api/workspaces/creation-policy` returns whether the signed-in user can create workspaces and which types are allowed (UI and Topbar use this instead of guessing from role alone).
- **Development workspaces (System settings)** — system admins can allow or block normal users from creating **Development** workspaces (`Allow logged-in users to create Development workspaces`; default **on**). Admins and system admins are not limited by this toggle.
- **Edit User — Password Setup** — system admins can leave the password unchanged, set a new password immediately, or send a password reset email when SMTP is configured (same pattern as **Add User**).

## Changed

- **Workspace create enforcement** — `POST /api/workspaces` applies the same policy as the creation-policy endpoint: normal users may create **Development** workspaces only when allowed; they become owner automatically. Admins retain full type choice.
- **Topbar settings menu (normal users)** — **Create workspace** stays visible but is disabled when creation is blocked; **Manage workspaces** goes to `/home/workspaces`; **Workspace settings** is hidden (admin-only surfaces unchanged).
- **Topbar dropdowns** — opening **Settings** or **Profile** closes the other menu so only one dropdown is open at a time.
- **Create workspace modal** — type selector shows only allowed types (no disabled ghost options for normal users on Development-only create).

## Fixed

- **Delete User** — confirm modal now reaches the API (removed stale confirm guard that caused a silent no-op).
- **Delete User** — users with reported or assigned activities can be removed; related records are reassigned in a transaction instead of failing with an internal error.
- **Delete User errors** — failure responses show the API message instead of a generic browser alert.
- **Security** — unrestricted workspace creation by any authenticated user (any type) is closed; policy is enforced on the server, not only in the UI.

## Upgrade notes

- **Public installer default version:** edit `docker-compose.yml` tags to `0.1.8` on `nogira-core`, `nogira-ui`, and `nogira-notification-worker`; set `REACT_APP_VERSION` to `'0.1.8'`.
- Run `docker compose pull && docker compose up -d`.
- **No manual NoGira SQL** — Prisma `migrate deploy` on core startup applies `allowLoggedInUserDevelopmentWorkspaceCreate` on `InstanceSettings` (default **true**, same behavior as before for existing installs).
- **PostgreSQL** stays on `postgres:14` — do not bump to PG 15+ without a PostgreSQL major-upgrade procedure ([deployment.md](../deployment.md)).
- From **0.1.7:** existing volumes compatible; keep **core**, **UI**, and **notification-worker** on the same semver.
- **Recommended:** upgrade from **0.1.7** directly; if you skipped **0.1.7**, deploy **0.1.6** then **0.1.7** first when you rely on development-workspace fields (environment, sprint, child table).

**Tracking:** NGB-045 (Manage Users delete / edit password), NGB-046 (Home workspace create + user Development workspace policy).
