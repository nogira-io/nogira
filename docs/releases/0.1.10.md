## Fixed

- **Hosted + self-hosted upgrades (reference catalogue)** — core startup now runs reference catalogue seeds after schema migrations so new `DEFAULT:*` schemes (screens/flows/type schemes) are present without manual `docker exec`.
- **Workspace create (templates)** — if scheme clone fails (missing catalogue data), the API returns an error instead of creating a workspace with null scheme IDs.

## Upgrade notes

- Bump all `nogira/nogira-*` image tags in `docker-compose.yml` to **0.1.10** (core, UI, notification-worker must match).
- Run: `docker compose pull && docker compose up -d`
- No manual SQL for NoGira schema migrations (applied on core startup).
- PostgreSQL remains pinned at `postgres:14` — do not change major version without a PostgreSQL migration procedure ([deployment.md](../deployment.md)).
