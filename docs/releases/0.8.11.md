# NoGira 0.8.11

**Release date:** 2026-11-09

**Forms re-enable** — Disabled forms can be turned back on from the workspace and system Forms lists. The Ban-only Disable action is replaced with a green/gray enable–disable toggle (same pattern as other settings). Enable reuses the existing publish API.

**Tracking:** **NG-753** / **NGB-100** / **NGF-083**. Public installer sample compose stays on **`latest`**. Candidate tag: **`dev-230ec88`**.

## Assets

- No GIF or screenshot required for this patch.

## Added

- Forms admin list: gray **Enable** toggle (`ToggleLeft`) on **Disabled** rows (**NG-753**).
- Client `enableForm()` alias that calls `POST /api/admin/forms/:id/publish` (**NG-753**).

## Changed

- Forms admin list: **Published** rows use green **Disable** toggle (`ToggleRight`) instead of Ban (**NG-753**).
- Draft rows no longer show a disable control on the list (publish remains in the form builder).

## Fixed

- After disabling a form, the **Disabled** tab still showed only **Disable**, so operators could not re-enable from the list (**NGB-100**).

## Verified

- Local UI deploy (`cicd-pipeline-local.sh --deploy -a ui`).
- Destin + UAT promote: **`dev-230ec88`**.

## Upgrade notes

- Pin `nogira-core`, `nogira-ui`, `nogira-worker`, and `nogira-mcp` to **0.8.11** together when the Hub tags exist, then `docker compose pull && docker compose up -d` (or keep sample `:latest` if that is your eval setup).
- Public installer `docker-compose.yml` is **not** version-pinned in this release (sample stays on **`latest`**).
- No manual SQL for NoGira schema migrations (applied on core startup).
- PostgreSQL remains pinned at `postgres:14` — do not change major version without a PostgreSQL migration procedure ([deployment.md](../deployment.md)).
