# NoGira 0.8.4

**Release date:** 2026-10-31

**Mobile own-work assignee is a default, not a lock** — After **0.8.3** pinned `assigneeIds=currentUser` on mobile Search/Activities, clearing Assigned = Myself (or changing other filters) no longer gets forced back. Entry paths (login, enroll, drawer categories, Wiki/Whiteboards → category) still default to Myself.

**Tracking:** **NG-734-P26**, **NGB-092**, **NGF-071**, **NGF-082**. Candidate tag promoted to UAT: **`dev-8a89ef3`**.

## Assets

- No GIF or screenshot required for this patch.

## Changed

- **Mobile filter preserve** — `/home/search` and `/workspaces/:id/activities` honor filter sheet Apply, including a cleared assignee. Layout and page effects no longer re-inject `assigneeIds=currentUser` while the user stays on the list (**NG-734-P26** / **NGB-092**).
- **Session remember** — Last mobile activity-list query is stored as-is; category navigation after Wiki/Whiteboards still applies the own-work default on that navigate.

## Fixed

- **NGB-092** — Mobile Search/Activities re-applied Assigned = Myself after the user removed it from filters.

## Upgrade notes

- Pin `nogira-core`, `nogira-ui`, `nogira-worker`, and `nogira-mcp` to **0.8.4** together when the Hub tags exist, then `docker compose pull && docker compose up -d`.
- Public installer `docker-compose.yml` is **not** bumped in this notes-only slice (hosted UAT already runs **`dev-8a89ef3`**).
- No manual SQL for NoGira schema migrations (applied on core startup).
- PostgreSQL remains pinned at `postgres:14` — do not change major version without a PostgreSQL migration procedure ([deployment.md](../deployment.md)).
