# NoGira 0.8.5

**Release date:** 2026-11-04

**Board data sources + Search More fields** — Create/edit Kanban and Scrum boards with All / Types / Filter data binding (server-side). On `/home/search`, add Labels, Priority, and catalogue select/user filters via **More fields ▾**.

**Tracking:** **NGF-087**, **NG-739**, **NGF-008**, **NG-740**, **NG-741**. Public installer sample compose stays on **`latest`**.

## Assets

- No GIF or screenshot required for this patch.

## Added

- **Board data source** — Create Board and Board settings: **All data** | **Types** | **Filter** (saved filter picker). Filtering runs on the server for board activities, backlog, and sprint feeds (**NG-739** / **NGF-087**).
- **Search More fields** — Right-aligned **More fields ▾** on `/home/search` to add Labels, Priority, SINGLE_SELECT / MULTI_SELECT / USER fields; 6-column wrap (**NG-740**).
- **Search API** — `priorityIds`, `labels` (pipe-separated), `ff` custom field filters; options payload includes `priorities`, `labels`, `filterFields`.
- **Saved views More fields** — `SavedFilterQueryV1` / `canonicalUrl` persist `labels`, `moreFields`, `priorityIds`, `fieldFilters` so `/home/filters` click restores the query (**NG-741**).

## Changed

- Board settings status mapping — × unassigns a status; pool chips stay inside Available statuses droppable.
- Public installer release rules — `nogira/docker-compose.yml` remains a **sample on `:latest`**; release notes/CHANGELOG still ship per version.

## Verified

- QA e2e **`saved-filter-query-persist.spec.ts`** (3 cases): ONBOARDING+TASK save; UI Save view; labels round-trip via Filters card click.

## Upgrade notes

- Pin `nogira-core`, `nogira-ui`, `nogira-worker`, and `nogira-mcp` to **0.8.5** together when the Hub tags exist, then `docker compose pull && docker compose up -d` (or keep sample `:latest` if that is your eval setup).
- Public installer `docker-compose.yml` is **not** version-pinned in this release (sample stays on **`latest`**).
- No manual SQL for NoGira schema migrations (applied on core startup).
- PostgreSQL remains pinned at `postgres:14` — do not change major version without a PostgreSQL migration procedure ([deployment.md](../deployment.md)).
